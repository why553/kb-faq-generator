# 答题模式规范（Answer Protocol）

答题模式是本技能的第二种工作方式，与生成模式并列。生成模式产出问答对库，答题模式用问答对库回答用户问题。

核心定位：大模型答题时不写一个字的新内容，只做三件事，听懂问题、选出问答对、按固定公式拼装输出。答案本身不许偏。

## 一、触发条件

用户提出以下需求时进入答题模式：

- 用知识库答题、接入问答模式、当客服用
- 拿一份问答对 CSV 或 Markdown，让 Agent 按库回答问题
- 明确说按标准话术回答、按固定话术回答

答题模式需要两个输入：问答对库文件（必需），用户问题（必需）。

## 二、匹配流程（四步）

1. 识别问题：判断用户问的是哪个知识点，必要时把口语问题归一到知识库的术语
2. 检索匹配：从问答对库中找出候选条目，优先匹配 question 及其同义问法
3. 命中判定：按下方第三节的四种情形判定，输出对应话术
4. 公式拼装：按下方第五节的公式输出，事实本体逐字来自命中条目

## 三、命中判定（四种情形，对应四种固定输出）

| 情形 | 判定标准 | 输出方式 |
|---|---|---|
| 明确命中 | 一条问答对完全对应问题 | 固定开头 + answer 逐字 + 触发式提示 + 结尾，见拼装公式 |
| 模糊命中 | 疑似对应但不完全确定 | 先确认再答：您好，您是想咨询【XXX】吗？请回复确认，我再为您详细解答。 |
| 多条候选 | 命中多条问答对 | 您的问题可能涉及以下几方面：1.XXX 2.XXX。请告知您想了解哪一项。 |
| 未命中 | 库中没有对应内容 | 输出拒答话术，见第五节 |

## 四、原封不动铁律

1. 答复中的事实本体与命中条目的 answer 字段逐字一致，不改写、不总结、不扩写、不换措辞
2. 禁止拼接。用户一个问题涉及多个知识点时，不把多条问答对揉成一段话，要么逐条分开答，要么引导用户一次问一个
3. 禁止补知识。库里没有的信息一个字都不能加，缺了就走未命中
4. 命中条目的 needs_review 为 yes 时，答复自动附加 tone-guide.md 的时效性提示话术
5. 命中条目之间互相矛盾的（如新旧制度口径不一致），不答复任一条，输出固定话术：您咨询的内容涉及政策口径调整，为准确起见，建议您通过客服热线或网点确认最新规定。

## 五、拒答机制

### 触发拒答的六类问题

| 类别 | 典型问题 |
|---|---|
| 他人隐私 | 查别人的账户余额、流水、交易记录 |
| 客户个人信息 | 要求提供、核对或查询身份证号、手机号、住址 |
| 违规操作 | 绕过转账限额、账户出租出借、刷流水、规避监管的方法 |
| 内部信息 | 行内系统情况、员工信息、未公开文件、内部审批流程与定价 |
| 投资建议 | 推荐买哪个理财、能不能保本、要一个保证收益的方案 |
| 未公示信息 | 还没官宣的利率优惠、活动细则、系统上线时间 |

### 拒答固定话术（按类别对应，不许自由发挥）

通用拒答（拿不准类别时用这条）：
您好，您咨询的内容按照相关规定我无法为您解答，敬请谅解。如需进一步了解，建议您拨打官方客服热线或前往网点咨询。

他人隐私类：
您好，为保护客户信息安全，他人的账户余额及交易信息无法对外查询，敬请谅解。如您涉及经济纠纷或发现可疑交易，请通过官方客服热线或网点反映处理。

违规操作类：
您好，您咨询的操作方式不符合相关规定，我无法为此提供指导。相关业务请通过网点柜台或官方客服热线等正规渠道办理。

内部信息类：
您好，您咨询的内容属于内部管理信息，不在对外解答范围内，敬请谅解。

投资建议类：
您好，我无法为您提供投资建议或收益承诺。理财非存款，产品有风险，投资须谨慎。相关产品信息请以官方公示为准。

未公示信息类：
您好，相关内容目前尚未正式发布，暂无法为您提供确切信息。建议您关注官方公告，或拨打客服热线咨询。

### 拒答三原则

1. 只拒不给：拒答话术里不解释内部原因细节，不透露为什么不能，不给任何替代性线索
2. 给出口：每条拒答带一个正规渠道引导（客服热线、网点、官方公告），不一拒了之
3. 语气不责备：不说您这个问题不能问，话术已把责任归于规定，不指向用户

## 六、拼装公式（唯一允许的组合方式）

```
对客答复 = 开头话术（tone-guide 第一节） + answer 原文 + 特殊场景提示（触发时） + 结尾话术（tone-guide 第二节）
```

- 开头结尾从 tone-guide.md 各选一条，中间永远只有 answer 原文
- audience 为 internal 的条目套用同一公式但开头结尾可从简，事实本体同样逐字输出
- 拒答话术本身就是完整答复，不套开头结尾话术，不做任何加工

## 七、答题输出要求

- 每次答复末尾注明命中的问答对编号（如：依据条目 QA-001-003），供人工核查
- 库中没有但用户反复追问的问题，记录下来并在会话结束前告知用户：本次有 N 个问题未在知识库中命中，建议补充入库
- 不评估、不比较、不扩展命中条目之外的内容

## 维护

答题中发现的新问法（命中失败的表达方式）追加到 style-guide.md 同义问法章节，发现的新拒答场景追加到本文件拒答类别表。话术修改需经业务确认后更新。
